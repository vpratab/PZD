# PZDR — verifiable transparency log + policy engine (2026-06-12)

Turns "Provable Zero Data Retention" from a signed-statement claim into an
end-to-end, third-party-auditable evidence trail. Follows the 2026-06-11
attestation-crate hardening.

## Problem fixed
The deletion-proof signature was verifiable, but the Merkle "receipt"
(`index/leaf/root/size`) carried no inclusion proof, no signed checkpoint, and no
consistency proof. An operator could equivocate (split-view), rewrite history, or
emit a root no client could tie a receipt to. For a Zero-Trust / compliance pitch
built on audit-admissible evidence, that was the central gap.

## Added — verifiable transparency log (RFC 6962)
- `services/pzdr-enclave/src/transparency.rs` — append-only Merkle log with
  inclusion proofs, consistency proofs, and signed checkpoints. Domain-separated
  hashing (`0x00` leaf / `0x01` node). Unit tests round-trip every tree up to
  size 40 and reject tampered paths and forked histories.
- `services/pzdr-enclave/src/policy.rs` — hash-pinned, default-deny policy engine
  (markers, SSN/PAN PII shapes, size, processor allow-list). Replaces the
  `<RESTRICTED` substring check. `policy_hash` is recorded in every proof; a test
  pins it to the Python reference value.
- `services/pzdr-enclave/src/INTEGRATION.md` — exact `main.rs` wiring (receipt now
  carries an audit path + signed checkpoint; proofs carry `policy_hash`).

## Added — independent verifier + conformance (no AWS, no Rust)
- `tools/pzdr_verify.py` — standalone auditor: proof signatures, inclusion vs a
  signed checkpoint, append-only consistency, hash-pinned policy, statement
  invariants, attestation binding. One command: `verify-bundle`.
- `tools/pzdr_ledger.py` — executable reference (ledger + policy) and spec.
- `tools/pzdr_gen_vectors.py` + `tools/conformance/` — deterministic golden
  vectors (12-session signed ledger, checkpoints, inclusion + consistency proofs,
  policy doc).
- `tools/pzdr_selftest.py` — **18-case adversarial suite**, all passing: forged
  signatures, post-sign tamper, tampered audit path, forged root, leaf
  substitution, equivocating/shrunk ledger, forged/swapped checkpoint, edited
  policy, false zeroization, result-leaking failure, contradictory decision,
  channel-key/measurement mismatch.
- `tools/run_all.sh` — one-command provability gate.

## Added — TypeScript SDK offline verification
- `sdk/typescript/transparency.ts` — signed checkpoint, inclusion, and
  consistency verification.
- `PZDRClient.verifyReceipt(...)` verifies the proof, checkpoint, leaf hash,
  and RFC 6962 audit path as one operation.
- `sdk/typescript/attestation.ts` validates raw COSE/CBOR Nitro documents,
  certificate paths, freshness, PCR0, and both enclave-generated public keys.
- `sdk/typescript/transparency.conformance.mjs` — cross-language test: the TS
  verifier validates the Python golden bundle (inclusion + consistency + leaf-hash
  agreement + negative control). **ALL PASS**, proving Python/Rust/TS agree on the
  hashing and canonical JSON byte-for-byte.
