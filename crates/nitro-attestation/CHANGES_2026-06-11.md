# nitro-attestation — hardening + test suite (2026-06-11)

## Security hardening (src/lib.rs)
1. **ES384 algorithm pinning** in `verify_cose_signature`: the COSE protected
   header MUST declare ES384 (-35) or verification refuses before touching key
   material. Closes the classic COSE/JWT algorithm-confusion class.
2. **CA BasicConstraints enforcement** in `verify_chain`: every certificate
   acting as an issuer in the validation path must carry cA=TRUE
   (OID 2.5.29.19). Prevents a compromised *leaf* from minting fake "enclave"
   certificates that would otherwise chain-validate.
3. **`Verifier::parse_and_verify`** one-call API: parse + signature + chain +
   freshness + optional PCR0 pin. This is the call the vsock parent proxy and
   TypeScript SDK backend should use; granular functions remain public.

## Test suite (tests/verifier_tests.rs) — 16 tests, 0 → 16
Synthetic Nitro documents in the exact NSM wire format (COSE_Sign1/ES384 over
CBOR attestation map, P-384 leaf signed by a generated test root; fixtures in
tests/fixtures/, created with openssl 3.0, chain sanity-confirmed by
`openssl verify`).

Positive: field extraction, full chain verification, one-call API, short chain
(leaf directly under root, empty cabundle), PCR pinning (incl. case
insensitivity), freshness.

Negative: tampered payload, signature grafted across documents, wrong root CA,
ES256 alg-confusion attempt, PCR mismatch (error detail check), stale doc,
future-dated doc, missing required fields, garbage inputs.

Robustness: deterministic ~5,800-mutation sweep over a valid document — parser
and verifier must never panic and must never accept content-altered documents.
PASS, zero panics, zero false accepts.
